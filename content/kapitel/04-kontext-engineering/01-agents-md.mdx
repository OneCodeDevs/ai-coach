Stell dir vor, du bekommst einen neuen Kollegen. Am ersten Tag setzt er sich an den Schreibtisch und fragt: „Wie starte ich das Projekt? Welche Regeln gelten hier? Was darf ich auf keinen Fall tun?" Normalerweise würde ein erfahrener Entwickler danebensitzen und alles erklären. Aber was, wenn der neue Kollege eine KI ist — ein sogenannter **Coding-Agent** (ein KI-Programm, das selbständig Code schreibt, Tests ausführt und Pull Requests erstellt)?

Genau dafür gibt es **AGENTS.md**: eine einfache Textdatei, die du in dein Projekt legst und die dem KI-Agenten alles erklärt, was er wissen muss.

## Was ist AGENTS.md?

AGENTS.md ist eine **Markdown-Datei** — also eine gewöhnliche Textdatei mit einfacher Formatierung (Überschriften, Listen, Fettdruck). Du legst sie ins Hauptverzeichnis (die „Wurzel") deines Projekts. Der Name `AGENTS.md` ist dabei kein Zufall: Verschiedene KI-Tools haben sich auf genau diesen Dateinamen geeinigt.

Das Besondere: **AGENTS.md ist herstellerübergreifend.** Egal ob du mit OpenAI Codex, GitHub Copilot, Cursor, Gemini CLI, Claude Code oder Aider arbeitest — sie alle suchen nach dieser Datei und lesen sie. Du musst also nicht für jedes Tool eine eigene Konfigurationsdatei pflegen. Eine Datei, viele Agenten.

AGENTS.md wird von der **Agentic AI Foundation** unter dem Dach der Linux Foundation betreut. Das ist keine einzelne Firma, sondern eine offene Organisation. Kein Hersteller kontrolliert das Format allein.

## Warum nicht einfach die README nutzen?

Jedes Softwareprojekt hat (hoffentlich) eine `README.md`. Die ist für **Menschen** gedacht: Wie installiere ich das Projekt? Wie sieht die App aus? Wo finde ich den Slack-Kanal des Teams?

Das Problem: Ein KI-Agent braucht andere Informationen als ein Mensch. Menschen wissen, dass `npm` und `pnpm` verschiedene Paketmanager sind. Ein Agent nicht — er nimmt das, was er am häufigsten in seinen Trainingsdaten gesehen hat, also vermutlich `npm`. Wenn dein Projekt aber `pnpm` verwendet, läuft alles schief.

**README bleibt für Menschen. AGENTS.md erklärt den Betrieb den Agenten.**

Stell es dir wie zwei Schilder am Eingang einer Werkstatt vor:
- Das eine Schild (README) sagt: „Willkommen! Hier bauen wir Fahrräder. Sprechstunde Mo–Fr."
- Das andere Schild (AGENTS.md) sagt: „Schraubenschlüssel 13er, Drehmoment max 25 Nm, Rahmen nie ohne Grundierung lackieren."

## Was gehört in eine AGENTS.md?

Typischer Inhalt, der KI-Agenten in echten Projekten produktiv macht:

- **Exakte Befehle** zum Starten, Testen und Prüfen des Projekts (nicht „führe die Tests aus", sondern `pnpm test --filter billing`). Ein Agent führt genau den Befehl aus, den du hineinschreibst. Wenn der Befehl stimmt, behebt er Fehler automatisch.
- **Stolperfallen**, die ein Neuling nicht kennt: „Verwende `pnpm`, nicht `npm`". „Die Testdatenbank braucht Docker". „Ohne `.env.example` startet nichts."
- **Konventionen**, die kein automatisches Prüftool (Linter) erkennt: „Keine Business-Logik in Controllern." „IDs sind ULIDs, keine UUIDs."
- **Sicherheitsgrenzen**: „Keine echten Zugangsdaten (Secrets) im Code." „Änderungen an `migrations/` nur im Vier-Augen-Prinzip."
- **PR-Format**: Wie sollen Titel aussehen? Was muss vor einem Commit laufen?

Wichtig: Schreib keine Befehle hinein, die lokal anders heißen als in der CI-Pipeline (dem automatischen Prüfsystem, das bei jedem Push läuft). Wenn in AGENTS.md `npm test` steht, aber in CI `pnpm turbo test` läuft, wird der Agent die Tests lokal grün machen — und CI schlägt trotzdem fehl.

## Verschachtelung: Mehrere AGENTS.md in einem Projekt

Große Projekte (sogenannte **Monorepos** — ein einzelnes Repository, das mehrere Apps oder Pakete enthält) profitieren von **mehreren** AGENTS.md-Dateien. Jede Datei gilt für ihren Bereich:

```
AGENTS.md                  # Gilt fürs ganze Repo: Toolchain, CI, Secrets
apps/web/AGENTS.md         # Nur für die Web-App: Next.js, App Router
packages/billing/AGENTS.md # Nur für die Abrechnung: Geschäftsregeln
```

Die Regel ist einfach: **Die nächste Datei gewinnt.** Wenn der Agent eine Datei in `packages/billing/` bearbeitet, liest er zuerst `packages/billing/AGENTS.md`. Was dort steht, hat Vorrang vor der Datei im Hauptverzeichnis.

Und über allem steht der **User-Prompt** — also das, was du dem Agenten direkt im Chat sagst. Deine Anweisung überschreibt jede AGENTS.md.

Kopiere nicht denselben Inhalt in jede Datei. Die Root-Datei enthält Querschnittsthemen (Toolchain, CI). Die Package-Dateien enthalten Fachliches. Wenn du kopierst, veraltet eine Kopie irgendwann — und der Agent bekommt widersprüchliche Informationen.

## Was AGENTS.md nicht ist

AGENTS.md ist kein Allheilmittel. Es ist **Onboarding-Text für Maschinen** — vergleichbar mit dem Einarbeitungszettel für den ersten Tag.

Was AGENTS.md **nicht** ersetzen kann:
- **Kein Ersatz für CI** (die automatische Prüfpipeline). AGENTS.md beschreibt Regeln. CI erzwingt sie.
- **Keine Skill-Library.** Lange Anleitungen mit 40 Schritten (z. B. „So machst du ein Release") gehören in einen **Skill** (dazu mehr in Lektion 4). Wenn du 40 Schritte in AGENTS.md packst, liest der Agent sie bei **jedem** kleinen Bugfix mit — das kostet unnötig Token (Recheneinheiten, die du pro Anfrage bezahlst) und verwirrt.
- **Keine Policy-Engine.** AGENTS.md kann bitten, aber nicht erzwingen. Wenn du verhindern willst, dass jemand Secrets committet, brauchst du einen technischen Check, nicht nur einen Satz.

## Migration von älteren Formaten

Manche Tools suchen noch nach `AGENT.md` (Singular) statt `AGENTS.md` (Plural). Falls du eine alte Datei hast: umbenennen und einen Symlink (eine Verknüpfung) für das alte Format anlegen, bis alle Tools aktuell sind.

Für spezifische Tools:
- **Aider**: Trage `read: AGENTS.md` in die `.aider.conf.yml` ein.
- **Gemini CLI**: Stelle den Dateinamen in den Einstellungen ein.
- **Cursor**: Liest AGENTS.md automatisch, zusätzlich zu seinen eigenen `.cursor/rules`.

AGENTS.md ist die herstellerübergreifende Einweisung. README erklärt das Projekt Menschen, AGENTS.md erklärt den Betrieb den Agenten. Die nächste Datei zum Edit gewinnt, der Chat überschreibt beide.
</Merksatz>
